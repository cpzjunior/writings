Games can be treated as independent software products while the computing capacity required to run them is consumed as an elastic, on-demand infrastructure service. The central thesis is that cloud gaming may be better understood as “AWS for games” than as “Netflix for games”: the scarce resource many players need to rent is not access to a large game catalog but access to sufficient computing capacity.

A personal experience motivates the argument: a player may buy an Xbox Series S or maintain an aging PC to avoid repeatedly purchasing gaming hardware, while discovering that subscription catalogs contain hundreds of games but only a small fraction are actually relevant. This creates two mismatched problems: excessive access to content the player does not want and hardware that gradually becomes insufficient for demanding new releases. The desired product is instead access to the computing capacity necessary to run a chosen game without requiring the player to purchase new hardware every generation.

The Netflix analogy is structurally limited because games differ from passive video content. A movie's computationally intensive work is largely completed during production; streaming primarily requires storing and delivering encoded video. Cloud gaming requires real-time execution: user input changes game state, CPU and GPU resources process it, a new frame is rendered and encoded, and the result travels over the network while input travels in the opposite direction. Consequently, computing capacity is not merely delivery infrastructure but an essential component of the service being consumed.

Catalog size therefore does not necessarily correlate with user value. A player may care about only a few genres or franchises, and hundreds of additional titles can provide little marginal utility. Games also impose greater experimentation costs than movies or television because players must learn mechanics, controls, systems, and progression, often over dozens of hours. If a user already knows which game they want to play, requiring them to subscribe to an entire catalog merely to obtain access to adequate hardware is economically and conceptually questionable. If the user owns a game such as Elden Ring but lacks a sufficiently powerful GPU, the problem is not game availability; it is computing capacity.

Cloud computing provides an analogous model. Instead of purchasing servers for several years, organizations rent infrastructure according to current requirements, scaling capacity up or down and shutting resources down when unnecessary. The important innovation is therefore not merely remote infrastructure but computing capacity transformed into an elastic resource that can be provisioned and consumed according to demand.

Applied to gaming, players could rent different classes of machines rather than permanently purchase GPUs or consoles. Lower-cost configurations could serve less demanding games or users willing to reduce graphical quality; intermediate configurations could target 1080p or 1440p; higher tiers could provide powerful GPUs, high frame rates, maximum graphical settings, or ray tracing. The player selects capacity according to the current game and desired experience.

A credit-based model could make consumption directly proportional to capacity. For example, a user could purchase R$100 of computing credits; inexpensive machines would consume fewer credits per hour, while cutting-edge configurations would consume more. A lightweight game played for twenty hours could use a low-cost configuration, while five hours of a demanding game could justify a premium machine. Unused credits would remain unused when the player does not play. Recurring plans could still exist, but their primary function could become a computing wallet rather than entitlement to a catalog.

This changes the relationship between price and experience: higher resolution, graphical quality, frame rate, or GPU performance costs more, while simpler configurations cost less. The fundamental unit of value becomes computing capacity consumed rather than the number of games accessible. Games remain necessary, but infrastructure becomes an explicit product rather than an invisible component bundled into a subscription.

Local hardware requires consumers to make long-term predictions. Purchasing a console or GPU means estimating how much computing capacity will be sufficient for several years despite uncertainty about future game requirements. Hardware does not suddenly become useless as new generations appear; rather, it gradually becomes inadequate for desired experiences, forcing compromises in resolution, graphical quality, ray tracing, or frame rate.

Cloud infrastructure can shift this obsolescence from individual consumers to providers operating at scale. New GPU generations can be deployed in datacenters, while older hardware can remain available as cheaper capacity for less demanding games. Obsolescence is not eliminated; responsibility for managing it moves from each consumer to the infrastructure provider. The consumer no longer needs to predict what hardware will be adequate five years from now and instead selects the capacity required for the game being played now.

The cloud also makes it possible to separate the game from the machine that executes it. A user can purchase a game independently of the hardware running it, using local hardware when adequate and remote infrastructure when it is not. The game remains an entertainment product while the machine becomes an independent service.

Under this model, a “Netflix of games” is not required for cloud gaming to succeed. Microsoft, Sony, Nintendo, and other platforms can continue selling games, maintaining libraries, offering exclusives, and operating their ecosystems. A separate company could specialize exclusively in gaming infrastructure without owning a game catalog or negotiating exclusives. Its role would be to provide machines capable of running games users already own, analogous to a cloud provider supplying servers for software owned by other companies.

Competition could therefore be divided into two layers. Game platforms could compete on games, prices, exclusives, services, and libraries. Infrastructure providers could compete on computing price, performance, latency, availability, geographic placement, and operational efficiency. Users could independently choose where to buy their games and where to run them.

The underlying distinction is between two products that have historically been bundled: access to games and access to the computing capacity required to execute them. Game subscriptions address the former through content distribution and catalog access. Cloud gaming addresses the latter through remote infrastructure. There is no inherent requirement that both be provided by the same company.

A player who wants only three games during an entire year could purchase those games and rent appropriate computing capacity whenever local hardware is insufficient. In that case, the required products are simply games plus computing infrastructure, not a game subscription. The cloud makes it possible to treat the game as a product that is purchased or subscribed to and the machine as a utility consumed on demand.

The resulting conceptual shift is from purchasing increasingly powerful hardware to keep pace with increasingly demanding games toward renting the computing capacity required to run whichever game the player chooses. The potential future model is therefore less a Netflix-style catalog subscription and more an AWS-style infrastructure layer for gaming.
